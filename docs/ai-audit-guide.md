# 驗收端 AI 稽核操作指南（scan-pii）

> 給收到去識別化文件、需要複核品質的驗收端人員。不需要寫程式，但需要會開終端機（命令提示字元／PowerShell）。
> 想快速了解整體架構，先看 README 的「批次個資稽核（AI 語意偵測）」一節。

## 這個工具做什麼

去識別化流程的第一層是**規則引擎**（18 種內建規則）：速度快、可預測，但只認「格式」——有標籤的病歷號、固定格式的電話等等。`scan-pii` 在其上追加第二層 **AI 語意偵測**：把文件文字送到你設定的 AI 端點，請模型找出規則漏掉的個資，例如：

- 沒有標籤的英文姓名（「由 John Wang 醫師主治」）
- 語序顛倒的就醫日期（「於 2024 年 5 月 1 日入院」——標籤在後面，規則抓不到）
- 不在標籤清單內的院內編號（「檢查序號 20240501-03」）

報告會把 AI 的發現分成三類：

| 類別 | 意義 | 處置 |
|------|------|------|
| **證實** | AI 找到、規則引擎也抓到 | 交叉確認，通常不用處理 |
| **補抓** | 規則引擎漏掉、AI 找到了 | **重點所在**：文件仍殘留可識別個資 |
| **無法定位** | AI 回傳的字串不在文字層中；可能是圖像內文字、萃取差異或模型誤讀 | 必須人工覆核，不能自動忽略 |

「補抓」的處置：退回文件提供者重新處理，或在網頁工具內手動圈選／新增自訂規則後重新輸出。

## 視覺稽核（PDF／PNG／JPEG）

圖像請求採用 [OpenAI 相容的 image_url content part](https://developers.openai.com/api/docs/guides/images-vision)；相容協定不代表每個模型都支援視覺，需以探測確認。

先執行 `npm run probe:vision`。此指令只把含隨機六位碼的合成圖片送到 `.env` 的端點，驗證 `image_url` 是否被接受且模型確實看得見圖片；HTTP 成功但讀錯碼仍算失敗。更換模型或端點後應重新探測。

```powershell
npm run scan-pii -- "已去識別化.pdf" --fail-on-findings --report audit.json
npm run scan-pii -- "已去識別化.png" --fail-on-findings
# 僅送出程式產生的全合成掃描 PDF，測試真實端點與退出碼（不在 CI 自動執行）
npm run test:vision
```

PDF 先用 pdf-lib 擷取頁面 JPEG XObjects（含巢狀 Form）作結構記錄，再用本機 Chrome／Chromium 與 PDF.js **渲染整頁**，逐頁把可見頁面送到模型。原始內嵌圖不等於完整頁面，因此不會直接把第一張內嵌圖當成整頁：旋轉、裁切、文字、向量表格與多張圖片都以合成後的頁面為準。Flate／PNG／遮罩等圖片由 PDF.js 合成處理，不依賴 JPEG 抽圖成功。每份 PDF 最多 100 頁，超出時明確失敗，不會靜默只掃前幾頁。

視覺結果帶頁碼；可定位到文字層時，對照內建規則的完整涵蓋範圍。圖像 PDF 沒有文字層時，圖中讀出的資訊列為「無法定位／待覆核」，仍會使 `--fail-on-findings` 退出碼為 1。這代表需要人工確認，不表示模型已經自動精準定位可遮蔽座標。模型不會直接修改文件。

視覺稽核需要本機 Chrome／Chromium；找不到時設定 `CHROME_PATH` 為執行檔絕對路徑。JSON 報告會包含模型讀出的值，應與文件同等保管。非 JSON、回應截斷、空白回應、連線失敗與不支援格式都不能當成驗收成功。網頁應用仍不引用模型程式、不呼叫模型 API；只有手動執行這些 CLI 才會送出資料。

## 隱私紅線（執行前先讀）

- AI 層會把**文件文字送到你設定的端點**——這是它的工作原理，不是外洩事故，但要遵守兩條線：
  1. **只用於已離開醫院信任邊界的文件**：也就是你們收到的去識別化產出。不要把醫院的原始病歷拿來跑這支工具。
  2. **端點要選得當**：研究用途的雲端服務（如國網中心）適合驗收去識別化產出；若要處理還沒去識別化的內容，端點必須部署在自己信任的內部網路。
- 目前網頁採 Cloud Run：文字必須經後端傳送至模型，PDF 視覺為選配。此頁說明獨立 CLI 驗收流程；部署與網頁資料流請參閱 [Cloud Run 說明](cloud-run.md)。

## 事前準備（每次換電腦做一次）

1. **安裝 Node.js 24**（亦可使用 22.13 以上的 22.x）：到 <https://nodejs.org> 下載安裝。裝好後開終端機輸入 `node -v` 確認。

2. **取得專案並安裝套件**（在專案資料夾內）：

   ```bash
   npm install
   ```

3. **申請 AI 端點**（以國網中心為例）：到 <https://portal.genai.nchc.org.tw> 申請服務，取得 API Key（`sk-` 開頭）與可用模型名稱（如 `Inkling-Small`）。任何 OpenAI 相容端點皆可（自建 vLLM、其他雲端服務）。

4. **建立設定檔**：

   ```bash
   # Windows（PowerShell）
   Copy-Item .env.example .env
   # macOS / Linux
   cp .env.example .env
   ```

   用記事本或 VS Code 編輯 `.env`，填入自己的三個值：

   ```ini
   OPENAI_API_BASE=https://portal.genai.nchc.org.tw/api/v1
   OPENAI_API_KEY=sk-你申請的Key
   OPENAI_MODEL=Inkling-Small
   ```

   `.env` 已列在 `.gitignore`，不會被提交到 git；**API Key 等同密碼，不要分享、不要貼到任何文件裡**。

## 執行稽核

```bash
# 單一檔案
npm run scan-pii -- 病歷摘要_去識別化.txt

# 多個檔案一次跑
npm run scan-pii -- 檔案1.txt 檔案2.txt 交接報告.md
```

- 支援 **`.txt` 與 `.md`**；DOCX／XLSX／PDF 請先用網頁工具開啟後另存／複製為純文字。
- 大檔案會自動分段（每段約 1800 字），逐段顯示進度；模型為推理型，**每段需數秒到十幾秒**，屬正常。
- 沒有設定 `.env` 時工具仍可執行，只是只跑第一層規則（報告開頭會註明）。
- 加上 `--fail-on-findings`：有任何「補抓」時以結束碼 1 結束（預設一律 0，僅供人工判讀），適合批次驗收或 CI 自動判定。檔案讀取或 AI 請求失敗一律結束碼 1 並列出失敗清單；單一檔案失敗不會中斷其他檔案。

## 解讀報告（實例）

```
=== 病歷摘要_去識別化.txt ===
內建規則：3 筆
  AI 語意偵測中… 1/1 段
AI 語意偵測：6 筆＝證實 3＋補抓 3＋無法定位 0
  ⚠ 補抓  英文姓名「John Wang」第 3 行（醫師英文姓名）
  ⚠ 補抓  醫療日期「2024 年 5 月 1 日」第 5 行（個管師電訪日期）
  ⚠ 補抓  識別碼「20240501-03」第 7 行（檢查序號）
```

讀法：

- **內建規則 N 筆**：第一層抓到的數量（這些值在文件裡已被標記處理）。
- **證實 3**：AI 與規則一致的 3 筆，可信度高，無需動作。
- **補抓 3**：上面 `⚠` 列出的就是殘漏——行號即殘漏位置，可直接到該行確認。本例中英文姓名、就醫日期、檢查序號都還留在文件裡，應退回或補處理。
- **無法定位**：文字文件需核對是否為模型誤讀或萃取差異；圖像 PDF 沒有文字層時，圖中真實可見的值也會列在這裡。先按頁碼查看原圖，不能只依數量推論模型品質或忽略結果。

## 常見問題

| 症狀 | 原因與解法 |
|------|-----------|
| `AI 端點回應 401` | API Key 錯誤或過期：檢查 `.env` 的 `OPENAI_API_KEY` |
| `AI 端點回應 404` | Base URL 或模型名稱錯：檢查 `OPENAI_API_BASE`（結尾通常是 `/api/v1`）與 `OPENAI_MODEL` |
| 顯示「未設定 .env，僅跑內建規則」 | 沒有 `.env` 或內容空白；仍可得到規則層報告 |
| 顯示「偵測到 .env，但此 Node 版本沒有 process.loadEnvFile」 | Node 低於 20.12：到 <https://nodejs.org> 升級（建議 22 LTS），或改用環境變數設定端點 |
| 中途失敗 `AI 偵測請求失敗` | 網路問題或端點暫時不可用；429（限流）與 5xx 會自動重試一次，再失敗才中止，重跑即可 |
| 想換模型 | 改 `.env` 的 `OPENAI_MODEL`；任何 OpenAI 相容端點的模型皆可 |
| 結果好像不準 | 確認文件語言與模型能力匹配；「無法定位」多時優先換模型；AI 結果僅供人工覆核，不做自動刪改 |

## 與網頁工具的關係

| | 網頁工具（瀏覽器） | scan-pii（CLI） |
|---|---|---|
| 對象 | 醫院端／產出去識別化文件的人 | 驗收端／複核文件的人 |
| 網路 | **零外傳**，所有處理在瀏覽器內 | 文字會送到你設定的 AI 端點 |
| 偵測 | 規則引擎（＋人工圈選） | 規則引擎＋AI 語意第二層 |
| 動作 | 產出去識別化文件與編碼表 | 只產報告，不修改文件 |

典型流程：醫院端用網頁工具產出去識別化文件 → 驗收端跑 `scan-pii` 複核 → 有「補抓」就退回或在網頁工具補圈選後重新輸出 → 再次複核到乾淨為止。
